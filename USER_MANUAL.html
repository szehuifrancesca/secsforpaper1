1. System Overview & Quick Start

The School-Based Exam Control System (SECS) is an offline, client-side web application designed specifically for primary school Paper 1 (Writing) marking. It completely eliminates error-prone shared spreadsheets, version conflicts, accidental formula overrides, and clerical calculation errors while safeguarding student data privacy under the Public Sector (Data Protection) framework.

1.1 Launching the System

  1. Navigate to the system folder: school-exam-control-system.
  2. Double-click start_secs.bat (or right-click index.html → Open with Microsoft Edge or Google Chrome).
  3. The application runs completely offline in your browser. No internet connection, web server, or software installation is required.

2.1 Real-Time Marked Script Tracking (Cohort & Class Level)

Markers have immediate, real-time visibility over their grading progress across three levels:

  • Top Header Badges:
    • 👥 Cohort Marked: Shows total cohort completion progress, e.g. 150/200 marked (75.0%).
    • 🏫 Class Marked: Shows the selected class bundle's progress, e.g. 24/28 marked (85.7%).
    • 📝 My Marked: Shows your personal cumulative marked count across all assigned classes.
  • Dropdown Live Annotations: When selecting a class in the dropdown, every class option displays its live progress tally (e.g., Humility 1 (Primary 4.1) [24/28 marked]).
  • Live Class Progress Card (Left Panel):
    • Animated progress bar showing the exact percentage of scripts completed for the active class.
    • Physical Stack Remaining Counter: Displays exactly how many hardcopy papers remain in your physical stack (e.g., 4 papers remaining in physical bundle), eliminating manual paper recounting.

2.2 Locating Physical Scripts

  1. Choose your filtering view: Form Class (e.g. Humility 1 (Primary 4.1)) or Mother Tongue Class (e.g. 4MT-1).
  2. Select the class bundle matching the physical stack in front of you.
  3. Use the Instant Bilingual Search Bar to locate any candidate immediately by typing:
    • Register Number (e.g., 5 or #05)
    • English Name (e.g., Wei Ting or Tan)
    • Chinese Characters (e.g., 陈 or 韦廷)
    • Script ID (e.g., SC-005)
  4. Click on the student card in the roster to open their score entry drawer.

2.3 Scoring & Boundary Guards

  • Content Mark: Enter marks awarded for plot development, idea elaboration, and theme relevance.
  • Language Mark: Enter marks awarded for vocabulary, sentence variation, paragraphing, and mechanics.
  • Automatic Sum & Percentage: The system calculates the total and percentage instantly upon keystroke.
  • Real-Time Input Guard: If a mark exceeds the prescribed rubric maximum (e.g., entering 9 when Content max is 7), the field flashes red with an alert blocking erroneous entry.

2.5 Random Pick Protocol & Mandatory Candidate Verification Gate

🛡️ Mandatory Physical Script Verification Gate (Zero Wrong-Candidate Scoring): In alignment with Singapore school grading realities, markers pick physical examination booklets randomly from bundles. To eliminate the risk of markers keying marks into the wrong candidate's record:
  • Input Shielding: Whenever an unmarked student is selected, scoring inputs (Content, Language, Feedback Tags, Remarks, and Save) are completely shielded and non-clickable (opacity-40 pointer-events-none).
  • Physical Verification Gate: A prominent amber banner displays: "⚠️ 1. Verify Physical Script Booklet Cover: Does this digital candidate match the physical paper booklet in your hand?" with Candidate Name (English & Chinese), Class, Reg No, and Script ID.
  • Explicit Marker Confirmation: The marker must click [✓ Yes, Booklet Matches Candidate (Unlock Marking)]. The badge turns green (✓ Verified Candidate Booklet) and automatically focuses the cursor on the Content mark input field.
  • Permanent Disable of Auto-Advance: The system strictly refrains from auto-pushing the next candidate's name onto the screen.

2.6 Pre-Advance Score Confirmation Dialog & Post-Save Booklet Picker

When the marker completes grading and clicks the blue 💾 Save & Confirm Score button:

  • Score Confirmation Summary: Displays Candidate Name, Class, Script ID, Content score, Language score, Total, Percentage, and chosen qualitative tags.
  • Keyboard Shortcut: Enter ↵ to Confirm: Simply press Enter ↵ on your keyboard to commit the score, or Escape (Esc) to amend.
  • Post-Save "Pick Next Physical Script from Pile" Card: Upon saving, SECS transitions to the Random Pick card. The marker glances at the physical cover of the next booklet in their pile and types the student's name, class, register number, or Script ID into the instant search bar to immediately open that candidate's verification gate.
  • 10-Minute Amendment Window: The 10-minute amendment grace window starts strictly only after score confirmation.

2.7 Understanding Marking Lock (Read-Only Mode)

🔒 Read-Only Marking Freeze: When the HOD locks the marking session after the deadline:
  • An amber banner displays: "🔒 Marking is currently FROZEN by HOD. The system is in READ-ONLY mode for review."
  • Score inputs, feedback tags, and the Save button are disabled to prevent inadvertent alterations.
  • Markers can still view and review all their graded scripts, marks, and remarks.

2.8 Key Personnel (KP) Moderation & Script Sampling Hub

Teachers designated as Key Personnel (KP) (e.g. Senior Teachers, Subject Heads, Level Heads) have direct access to standardisation and moderation tools directly from their Marker Portal:

  • Dual-Tab Navigation: Authorized KP markers see a navigation bar at the top with two dedicated tabs:
    • ✏️ My Marking Entry: Standard physical script scoring interface for their assigned bundle.
    • ⭐ KP Moderation & Script Sampling Hub: Full paper-wide moderation workspace, equipped with a live badge showing total recommended scripts awaiting check.
  • View All Scripts Across All Markers: KP moderators can inspect every candidate script registered under the active paper, including unmarked scripts, marked scripts, and previously moderated scripts across all teachers.
  • Intelligent Standardisation Sampling Recommendations: One-click filter pills instantly identify scripts meeting official quality audit triggers:
    • 🎯 Recommended Combined: Prioritised composite queue encompassing all critical quality triggers.
    • ⚖️ Borderline Pass (48% - 52%): Scripts hovering immediately above or below the 50% passing threshold.
    • 🌟 Borderline Quality (78% - 82%): Scripts nearing distinction/quality cut-off.
    • ⚡ Content vs Language Discrepancy: Unbalanced scripts with >20% variance between Content and Language criteria.
    • 🎲 Random 10% Sample: Representative cross-section for general standardization audit.
    • 🚨 Pupils-at-Risk (PAR < 50%): Rapid identification of candidates requiring learning support.
    • ⏳ Unmarked Scripts: Immediate visibility into unentered scripts to monitor cohort pace.
  • Side-by-Side Moderation Drawer:
    • Original Marker Evidence: Displays First Marker Code, initial Content score, Language score, Total, Percentage, awarded Feedback Tags (Green/Pink), and Teacher Notes.
    • Moderation Controls: KP enters Moderated Content and Language scores. The system calculates real-time Variance Delta (±Δ) with color cues (green for agreement, amber/red for adjustments).
    • Moderation Rationale: Mandatory justification log ensures transparent audit trails aligned with standardisation meeting guidelines.

3. HOD & Key Personnel Operational Guide

As HOD or Examination Lead (authenticated via confidential HOD Master Passcode), you have complete administrative control over multiple examination levels, active papers, archived papers, cohort class bundles, rubrics, sample check moderation, and official reports.

3.1 HOD Authentication & Executive Paper Control Deck

  • Executive Paper Control Deck: Pinned permanently across the top of the HOD interface:
    • Active Paper Metadata: Level, Subject, Component, Academic Year, and Rubric Max bounds (e.g., 15 Max (7C + 8L)).
    • Status Badges: Real-time indicators for 🟢 Active Marking, 🔒 Marking Frozen, and 📦 Archived Paper.
    • Live Candidature & Marked Tracking: Displays total candidate count and live percentage completion (e.g., 150 / 200 (75%)).
    • Quick Actions: 1-click access to 📁 Papers & Archives, ✏️ Edit Paper Settings, 🔒 Lock/Unlock Marking, and 📦 Archive Paper.

3.2 Dedicated "Register New Paper" Tab & Exam Studio

To ensure a distraction-free administration experience, new paper setup is housed in a dedicated top navigation tab (➕ Register New Paper), separated from ongoing marking cohorts in 📁 Exam Studio:

  • Dedicated Tab: ➕ Register New Paper (tabRegisterPaper):
    • A streamlined 5-step registration wizard: (1) Paper Title & Term, (2) Assessment Level & Rubric Presets, (3) Candidate Roster Population (Clean Roster or 1-Click Copy from existing paper), (4) Primary Marker Allocation, and (5) Multi-Device Shared Sync.
    • Clicking "🚀 Register & Launch Paper" creates the paper, auto-publishes it to the shared drive manifest, and automatically transitions to Exam Studio.
  • Left Rail — Paper Navigator & Archived Papers (Exam Studio):
    • Active Papers List: Interactive cards displaying candidate tallies, marked progress bars, and marker team size. Click "Switch To" to instantly switch paper context. Supports 1-click archiving, duplicating, and editing, with a direct shortcut to the Register New Paper tab.
    • Archived Papers: Safely stores concluded exam cycles in read-only freeze, strictly shielded from active roster selectors. Retains complete candidate scores and audit logs with 1-click restoration to active marking anytime.
  • Right Rail — Active Paper Setup & Cohort Workspace:
    • Step 1: Paper Specifications: Configure Examination Title, Level, Subject, and Rubric Presets (e.g., P3/P4 MT 7C+8L=15 vs P5/P6 MT 20C+20L=40).
    • Step 2: Candidate Roster Management: Candidate table with class-level dropdown filtering (rosterClassFilter), real-time search (by Register No, English/Chinese name, Script ID), 1-click cross-paper roster cloning, and bilingual CSV roster upload with UTF-8 BOM protection.
    • Step 3: Marker Team & KP Moderation: Allocate markers (M01-M20) and check KP Moderator to delegate sample check and moderation rights without sharing the master HOD password.
    • Step 4: Paper Security & Passcodes: Set paper-specific marker passcode (isolating cohorts) and configure the confidential KP Moderator Authorization PIN / OTP (e.g. MOD88) with an optional 1-click random PIN generator. Both passcodes are prominently summarized on each paper card in the Papers Hub.
    • Class & Cohort Bundles (Bottom Section): Visual card grid for all Form Classes and Mother Tongue Banded Classes in this paper. Supports ✏️ Rename Class, 🗑️ Delete Class Bundle, + Add New Class Bundle, and individual + Pupil additions.
📋 How to Add Rosters & Class Bundles to Different Exam Papers (4 Seamless Workflows):
  1. Method 1: 1-Click "Copy from Paper" (Cross-Paper Roster / Class Clone) — [RECOMMENDED]: In the Right Rail Step 2, click 📋 Copy from Paper. Select any source paper, choose "All Classes" or a specific Form Class / MT Class, select Append or Replace mode, and click 📋 Copy Pupils Now. Candidates are imported with clean, unmarked status and sequential script numbers without re-uploading spreadsheets.
  2. Method 2: Inherit Roster upon Registering a New Paper: In the Left Rail (Register New Paper tab), select Student Roster & Classes: Copy roster from [Existing Paper]. The new paper is immediately created with the full cohort and class structure ready for marking.

  4. Method 4: Duplicate an Entire Exam Paper: In the Left Rail or Manage Registry, click 📋 Duplicate to clone the entire paper (cohort, rubric, and markers) with scores reset to unmarked.

3.3 Live Monitoring: Master Consolidation (Tab 2)

  • Dynamic Tracking Banner: Top banner shows real-time cohort statistics: Total Marked: X/Y (Z%), Unmarked: N, and Moderated: M.
  • Contextual Subgroup Progress: When filtering by a specific class or marker, the banner dynamically highlights that subgroup's completion (e.g., Selected Class: 4 Harmony [24/28 marked, 4 remaining]).
  • Filter Dropdown Counts: All filter dropdowns annotate each selection with real-time marked counts.
  • Dual-Mark & Moderator Code Display: Moderated scripts prominently display the final mark alongside an audit badge: 14 (Orig: 13, +1), and both original marker and moderator code (e.g., Mod: M01 or Mod: HOD) are clearly shown for total traceability.

3.4 Quality Assurance: HOD Sample Check & Moderation (Tab 3)

Standardised Examination Moderation Protocol:
  1. Smart Sampling Filters: Automatically flags target scripts: Borderline Pass (48% - 52%), Borderline Quality Pass (78% - 82%), Content/Language Discrepancy, and Random 10% Sample.
  2. Side-by-Side Moderation Drawer: Inspect the first marker's scores, tags, and qualitative comments, enter moderated scores, and observe the live variance delta ($\pm\Delta$). Both First Marker code and Moderator Code are attributed in the table.
  3. Indelible Historical Retention: Applying moderation updates the final score while permanently retaining the first marker's original score and moderation rationale for audit defense.

3.5 Independent Per-Paper Marking Lock / Read-Only Freeze Control

SECS provides granular, per-paper marking control, allowing the HOD to freeze or open individual assessment papers independently:

  • Independent Paper Scheduling: The HOD can freeze Primary 4 when grading concludes, while keeping Primary 5 actively open for marking. Different assessment levels never interfere with each other.
  • 4 Visual Paper Badges: 🟢 Active Marking, 🔒 Marking Frozen, ⚠️ Draft (Unreleased), and 📦 Archived.
  • 1-Click Freeze Toggles: Toggle freeze directly on each paper card in the Left Rail (🔒 Freeze / 🔓 Open) or via the header button (🔒 Freeze Marking) above the active workspace.
  • Instant Shared Folder Broadcast: Lock state updates broadcast to exam_master_${examId}.json within seconds, placing markers into read-only review mode automatically.

3.6 Item Analysis & Marker Calibration (Tabs 4 & 5)

  • Tab 5 (Marker Calibration): Evaluates inter-rater reliability across all markers. Identifies grading tendencies: Calibrated ($\pm 1.5$ marks), Lenient/Dove, Strict/Hawk, and tracks HOD sample checks and moderation deltas.

3.10 Database Backup, Transfer & Restore

  • All exam data is maintained in the browser's local storage sandbox.
  • Backup / Export: Click 💾 Backup DB (JSON) to save a snapshot named SECS_Exam_Database_Backup_YYYY-MM-DD.json.
  • Restore / Transfer to Another Laptop:
    1. Copy the backup JSON file and the school-exam-control-system folder to the new laptop.
    2. Open SECS in Edge or Chrome.
    3. Click 📂 Restore DB (JSON) and choose your backup file. All students, scores, tags, and settings are restored in seconds.

3.11 Multi-Paper & Multi-Marker Shared Folder Live-Sync Guide (Platinum Standard)

📁 Concurrent Multi-Device Marking via School Shared Drive (e.g. S:\...):

SECS features a Decoupled Shared Folder Live-Sync Engine using Microsoft Edge's native File System Access API. Each teacher auto-saves to their own file (secs_sync/marker_${examId}_${markerCode}.json), and moderators save to partitioned files (secs_sync/moderation_${modBy}.json), preventing file-locking collisions even when 20+ teachers and multiple moderators mark simultaneously across multiple papers.

  • HOD Setup & Automatic Sync: Place the SECS folder on the school shared drive (S:\Departments\...). Click 📁 Link Shared Folder in the top navigation bar. Any change made to student rosters, class bundles, or rubrics automatically synchronizes to the exam master file in the background.
  • Marker Workflow: Markers open index.html from the shared folder, select their target assessment paper (e.g. P4 or P5), enter their Marker Code and PIN, and grade. Marks auto-save silently to their individual JSON file.
  • KP Moderator Live Queue & Partitioned Moderation: Multiple Key Personnel and the HOD moderate concurrently without conflicts, auto-saving to separate moderation_${modBy}.json files in real time.
  • Serial Write Queue & 5-Tier Exponential Retry Backoff: All atomic disk writes are processed via an asynchronous promise queue (enqueueWrite) with a 5-tier exponential retry loop (150ms-2400ms + randomized jitter), eliminating Windows SMB file contention and sharing violations (STATUS_SHARING_VIOLATION).
  • Self-Healing Snapshot Push & Pending Queue: Marker score submissions construct complete snapshots from memory and queue delayed writes in pendingPushes, guaranteeing zero lost marks during transient network dips.
  • Adaptive 3.5s Polling & Zero-Lag Typing Throttle: Background polling pauses while teachers type scores or notes, eliminating input lag while reducing shared drive I/O traffic by 45%.
  • Autonomous 12s Watchdog & 1-Click Reconnect: An independent 12-second watchdog auto-recovers background sync loops, while 1-click permission prompts allow instant reconnects without file-dialog friction.
  • Zero Shared Folder Maintenance: Archiving papers automatically hides them from active queues while preserving complete historical files on disk. No manual file deletion is ever needed.

4. Frequently Asked Questions (FAQ)

Q1: Can we use SECS for more than 5 form classes?

Yes, absolutely. SECS dynamically adapts to any number of classes (e.g. 6, 8, 10, 15, or more classes). The roster, dropdowns, and comparison tables generate automatically based on the class names present in your CSV file.

Q2: Can I move the system to a USB thumb drive or my Desktop?

Yes. You must copy or move the entire school-exam-control-system folder, because index.html references scripts in the js/ folder. Alternatively, you can create a shortcut to start_secs.bat on your Desktop without moving any files.

Q3: Why do Chinese characters display properly without corrupted symbols (mojibake)?

SECS includes explicit UTF-8 Byte Order Marks (BOM, ﻿) and Microsoft Word HTML headers across all CSV, Excel, and Word exports. This guarantees that Chinese characters (如: 陈韦廷, 蔡恩熙) render flawlessly in Microsoft Excel and Word on Windows.

Q4: Can markers see marks or feedback entered by other teachers?

No. The Marker Portal is strictly sandboxed. Markers only see their own assigned scripts, input controls, and personal grading history. Peer marks, cohort statistics, and moderation deltas require the confidential HOD master passcode or authorized KP moderation rights.

Q5: What happens if an error is found after marking has been frozen?

The HOD simply clicks 🔓 Unlock Marking in the top header or paper card. The marker can then amend the score, save the change, and the HOD can re-freeze the system.

Q6: Can different markers mark concurrently from different laptops in a shared folder?

Yes! Using the Shared Folder Live-Sync Engine, multiple markers open index.html from the school shared network drive (S:\) on their respective laptops. Each marker auto-saves to their own file (marker_${examId}_${markerCode}.json), eliminating file collisions, while HOD and KP moderators view live incoming marks and score tallies in real time.

Q7: Do you recommend storing different papers (e.g. P4 and P5) in the same shared folder or different folders?

We strongly recommend storing them in the same shared folder (e.g. S:\Departments\MotherTongue\Exam2026\). SECS uses paper-isolated filenames (exam_master_${examId}.json, marker_${examId}_${markerCode}.json) and a unified manifest. Storing them in a single folder allows markers and moderators to switch between papers seamlessly without re-linking shared drives, while ensuring 100% data separation.

Q8: Can two papers be active at the same time?

Yes. Multiple papers can be active simultaneously (e.g. P4 Paper 1 and P5 Paper 1). Markers grading P4 and markers grading P5 can grade concurrently on their own laptops. HOD can also freeze P4 once finished, while P5 continues marking uninterrupted.

Q9: If an exam paper is archived, do we need to delete any files from the shared folder?

Strictly NO. Archiving automatically updates the manifest to hide the paper from active marking queues, while retaining all historical candidate records and moderation logs on disk for audit compliance. No manual file management is ever required on the shared folder.
